METHODS — BWoS queue on Apple Silicon

Platform: Apple MacBook Air with M4 SoC, 16 GB unified memory, macOS 26.5.2. The configured system has 10 (M4 configuration supplied for this run; sysctl query unavailable) CPU cores; this experiment uses exactly two application threads, one owner and one thief. No NUMA or multi-queue pool experiment is performed.

Compiler and dependency: Apple clang version 21.0.0 (clang-2100.1.1.101); C++20; optimization enabled with -O2. NVIDIA stdexec is fetched at configure time from https://github.com/NVIDIA/stdexec.git, branch main, using CMake FetchContent. The resolved stdexec commit for this run is 3258236616e1996dd5d1650721d8a408a1652da2. The queue header is include/exec/detail/bwos_lifo_queue.hpp. The inspected interface is experimental::execution::bwos::lifo_queue<T>, constructed with (num_blocks, block_size), with push_back(T)->bool, pop_back()->T, and steal_front()->T. A value-initialized T signals empty, so task IDs are nonzero.

Correctness procedure: Before any timed throughput measurement, the program runs 20 independent repetitions unless --skip-correctness is specified. Each uses one owner, one thief, a queue with four blocks and eight entries per block, and 1,000 task IDs. The owner retries failed pushes. The thief repeatedly calls steal_front while the owner is publishing, and stops after owner completion and an empty result. After joining the thief, the owner drains pop_back. The check passes when the number stolen plus the number drained equals 1,000. Any failed repetition stops the program before throughput; exported throughput is marked invalid and the throughput plot is omitted.

Throughput procedure: At each nominal steal target (0%, 1%, 5%, 10%, and 20%), the owner performs push bursts followed by matching pop bursts on a four-block queue with 256 entries per block. Each burst contains 768 tasks, creating a bounded steal window across three blocks while keeping owner operations in tight loops. Owner throughput counts push and pop API calls per elapsed second, including push retries when the bounded queue reports full. One thief calls steal_front. For nonzero targets, a spin-wait inter-steal delay is calibrated by short 180 ms pilot trials: the delay is multiplicatively adjusted toward the requested ratio of successful steals to completed owner push/pop transactions, and at most eight calibration iterations are used. The selected delay and each pilot's achieved fraction are printed in the log. Targets are nominal; achieved fractions are emitted per timed sample. At 0%, the thief thread remains present but does not call steal_front.

Each timed sample lasts 2 seconds; the CLI defaults to 20 throughput repetitions per target and permits --reps N, --duration S, and --out DIR. Reported summaries use the arithmetic mean, sample standard deviation, and two-sided 95% Student-t confidence interval for the mean (normal approximation when degrees of freedom exceed the included lookup table). Relative throughput is normalized to the mean at 0%; the plot uses that same normalization and sample-standard-deviation error bars. Correctness repetitions remain fixed at 20 and are controlled separately by --skip-correctness.

Reproducibility note: archive the generated results.csv, summary.csv, benchmark log, METHODS.txt, compiler version, and stdexec commit together. These figures describe this machine, operating-system scheduling state, compiler, and dependency revision; they are qualitative and are not comparable to x86/NUMA server results.
